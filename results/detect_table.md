# T4b 影像偵測式規則（detect）：策略只從收到的影像自行判斷是否「看不見」

規則（`code/run_t3t4.py --rule detect`）：兩個偵測器**同時開**（與 mode 無關）。black：所有相機影像的像素均值 < 1.0（uint8 尺度，約 1/255 滿刻度）；freeze：當前影像與策略上一步收到的影像逐像素完全相同。偵測到時不重規劃、繼續執行手上 chunk；chunk（100 步）用完才被迫重規劃（同 oracle）；未偵測到時照固定 n 規則（k >= n 就重規劃）。真實失明區間只用於記錄（latency、false_detect），不參與控制。env seed / t0 與 T2、oracle 同（程式內 assert）。McNemar 為精確二項檢定（「det only」= detect 成功而對照失敗的 episode 數）。

「detected steps / L」< 1 是因為 episode 在失明結束前成功而提前結束（steps < t0+L）。延遲 = 失明區間內第一次偵測的步數 − t0（0 代表失明第一步就偵測到）；false detect = 失明區間外的偵測步數。

## 誤觸發（L=0）

- n=50, L=0（無失明）100 episodes：detect 規則成功 89/100 = 0.89 [0.81, 0.94]；T2 固定 n=50 91/100；detect 單贏 0 / T2 單贏 2，McNemar p = 0.500。
- 誤觸發：偵測步數合計 0（0/100 個 episode 有任何偵測）；每 episode 平均偵測步數 0.000，replans_total 平均 6.51。

## 偵測器校準（無失明，seeds 100–119，n=100 固定規則，20 episodes）

- 影像（uint8 尺度 0–255）全畫面均值分布：min 38.97，p1 39.04，中位 40.41，p99 41.67，max 42.12（6183 步）。黑畫面門檻 1.0（即 1/255 滿刻度；全黑均值 = 0）。最小均值與門檻的比值 39x，無誤報：black 偵測 0 步。
- 相鄰兩步影像逐像素完全相同的步數：0 / 6183（freeze 偵測誤報）。
- 同一批 episode 的規則層面誤報（black 或 freeze 任一）= 上面兩項之聯集；見下方「誤觸發（L=0）」一節的 100-episode 統計。
